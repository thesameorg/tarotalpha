# Как здесь документируют

Проза по-русски, код и комментарии по-английски. Оснастка в `scripts/` — исключение, линтер изымает её от `LNG001`.

## Шаг 0. Документ описывает «сейчас»

Первое правило, остальные после него. Документ говорит, как устроено и почему — на момент чтения. Не «раньше было» (это `git log`), не «будет» (это GitHub Issues), не «сделано/осталось» (это PR). Правка, из-за которой документ начал врать, чинит его в том же PR; «обновим потом» не бывает. ADR — единственное исключение: он заморожен в момент решения, а «сейчас» у него — статус в шапке и ссылка на отменяющий.

## Шаг 1. Нужен ли документ вообще

Три фильтра, в этом порядке. Сработал любой — документа нет.

1. **Выводится из кода?** Не документируем: список полей и эндпоинтов устаревает в тот же день.
2. **Это состояние?** «Что сделано» — PR и `git log`, «что осталось» — issue; в документ ни то ни другое не идёт.
3. **Восстанавливается по коду за минуту?** Не документируем.

Документируем только то, что **из кода не восстанавливается никогда**:

- поведение чужих систем — «Binance отдаёт klines пачками по 1000, лимит веса 6000/мин на IP»;
- отвергнутые варианты и цену решения — иначе их переизобретут;
- инварианты между частями, не выраженные типом;
- процедуры с ручными шагами и последствиями снаружи;
- потоки данных: что чем триггерится, откуда берёт, куда отдаёт.

**Issue — не хранилище знания.** Задача — след работы. Что понадобится через полгода, живёт в `docs/`: решение в `docs/adr/`, устройство в `docs/flows/`, факт в `docs/reference/`. Номер issue допустим как метка («#12»), но не как ссылка, без которой текст непонятен.

## Шаг 2. Куда

| Вопрос | Место |
| --- | --- |
| «как работает **сейчас**», ≤3 строк | комментарий у кода |
| «как работает **сейчас**», длиннее | `docs/<область>/<тема>.md` + ссылка из кода |
| «какие данные куда текут» | `docs/flows/<процесс>.md` |
| «как **сделать**» (руками, с последствиями) | `docs/runbooks/<действие>.md` |
| «**почему** решили так» | `docs/adr/NNNN-<решение>.md` |
| «что это **слово** значит» | `docs/glossary.md` |
| «что **изменилось**» для пользователя | заголовок коммита и описание PR, не документ |
| «что делать **дальше**» | issue в GitHub, не документ |

Компас, когда непонятно: **читают подряд или сверяются?** Сверяются — `docs/reference/` или `docs/glossary.md`. **Делают по шагам или понимают?** Делают — runbook. Понимают — `docs/adr/` или `docs/flows/`.

## Шаг 3. Сколько

- **Шапка файла — до 10 строк.** Только первый блок **выше кода**; импорты и директивы кодом не считаются. Отвечает на «что это и почему так устроено», содержимое файла не пересказывает.
- **Всё остальное — до 3 строк.** Один комментарий на секцию, и только о том, чего не видно в коде: «сделано так, потому что», «работает только при», «здесь грабли».
- **Режется без разговора:** шапка, пересказывающая сигнатуры; ченджлог («раньше было», «переименовано в TA-x») — это `git log`; список шагов, который и есть код ниже. Отвергнутый вариант остаётся: «пробовали X, стоило Y».
- Не влезло — страница в `docs/` и ссылка из кода в одну строку.
- **Ссылка двусторонняя:** комментарий даёт путь к документу, документ называет свои файлы. Обе стороны проверяет линтер (`CMT003`, `MD004`).

Escape hatch: `docs-lint: allow` внутри блока — для текста, который обязан стоять ровно здесь. Обходить им требование сокращать нельзя.

## Шаг 4. Форма документа

Вторая строка любого дока в `docs/` — статус, дата, вердикт одним предложением:

```markdown
# Кэш свечей

> актуально · 2026-09-10 · свечи кэшируются на 5 минут по ключу asset+timeframe, снапшот расклада пишется отдельно и живёт вечно
```

Статусов ровно шесть, других нет:

| Статус | Значит |
| --- | --- |
| `актуально` | описывает работающий код, поддерживается |
| `реализовано` | решение в коде, документ заморожен |
| `справочник` | предметная область, не наш код |
| `черновик` | кода ещё нет, читать как замысел |
| `заморожено` | не поддерживается сознательно |
| `устарело` | врёт, читать нельзя; в той же строке ссылка на замену |

- **Имя файла — это вопрос.** `candles.md` — тема; `candles-caching.md` — вопрос.
- **Каждая папка `docs/` имеет `README.md`** со строкой на документ: имя и на какой вопрос он отвечает.
- **ADR не редактируют.** Передумали — новый со ссылкой «Отменяет ADR-NNNN», старый получает `устарело`.
- **Секретов в тексте нет.**
- **Термины бери из `docs/glossary.md`**, на месте их не изобретают.

## Шаг 5. Нейминг: имя — это обещание

В имени стоит то, **что происходит**. Слой, тип и тема в имя не идут.

| Плохо | Почему | Хорошо |
| --- | --- | --- |
| `utils.ts`, `helpers.ts` | ничего не обещает | `slugify.ts`, `atr.ts` |
| `handleData()` | слой + тип | `mergeKlines()` |
| `ReadingManager` | «менеджер» — не действие | `ReadingTeardown` |
| `docs/cards.md` | тема, не вопрос | `docs/flows/card-to-candles.md` |

Тест: **имя обещает ровно то, что внутри, и ничего сверх?** Один термин — одно имя во всей кодбазе.

## Шаг 6. Перед тем, как закрыть задачу

**Доки, которые ты не трогал, могли начать врать.** Шаг полного пути (`CLAUDE.md`, «Порядок работы»):

```bash
pnpm run related
```

Команда выдаёт документы, говорящие о том же, что изменил PR. По каждому хватает вердикта во второй строке; целиком открываешь только тот, что про сделанное, и отвечаешь: **противоречит ли он сделанному?** Противоречит — правь в этом же PR. Устарел целиком — статус `устарело` со ссылкой на актуальный. Не про это — ничего.

Линтер найдёт мёртвую ссылку, но не найдёт двух документов, утверждающих разное. Это работа читателя.

## Проверка

| код | что |
| --- | --- |
| CMT001 | блок комментариев: шапка файла > 10 строк, в теле > 3 |
| CMT002 | то же для python-docstring |
| CMT003 | код ссылается на несуществующий документ |
| MD001 | markdown вне `docs/` и `.claude/` |
| MD002 | док не вписан в README своей папки |
| MD003 | нет строки «статус · дата · вердикт» |
| MD004 | док ссылается на несуществующий путь |
| MD005 | PR тронул файлы, которые док зовёт своими, док не обновлён |
| LNG001 | кириллица в комментарии кода |
| NAM001 | имя файла или папки ничего не говорит |
