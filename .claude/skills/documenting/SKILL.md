# Как здесь документируют

Проза — по-русски, термины и код — по-английски. Комментарии в коде — по-английски: они стоят вплотную к английским идентификаторам. Оснастка в `scripts/` — исключение, её читает владелец, а не приложение, и линтер её от `LNG001` изымает.

## Шаг 1. Нужен ли документ вообще

Три фильтра, в этом порядке. Сработал любой — документа нет.

1. **Выводится из кода?** Не документируем. Список полей, эндпоинтов, переменных устаревает в тот же день.
2. **Это состояние?** «Что сделано», «что осталось» — не документ. Состояние живёт в `tasks/` и там же умирает.
3. **Восстанавливается по коду за минуту?** Не документируем.

Документируем только то, что **из кода не восстанавливается никогда**:

- поведение чужих систем — «Binance отдаёт klines пачками по 1000, лимит веса 6000/мин на IP»;
- отвергнутые варианты и цену решения — иначе через полгода их переизобретут;
- инварианты между частями, не выраженные типом;
- процедуры с ручными шагами и последствиями снаружи;
- потоки данных: что чем триггерится, откуда берёт, куда отдаёт.

**`tasks/` — не хранилище знания.** Задача — след работы. Всё, что понадобится через полгода, живёт в `docs/`: решение — в `docs/adr/`, устройство — в `docs/flows/`, факт — в `docs/reference/`. Номер задачи в тексте допустим как метка («TA-006»), но не как ссылка, без которой текст непонятен.

## Шаг 2. Куда

| Вопрос | Место |
| --- | --- |
| «как работает **сейчас**», ≤3 строк | комментарий у кода |
| «как работает **сейчас**», длиннее | `docs/<область>/<тема>.md` + ссылка из кода |
| «какие данные куда текут» | `docs/flows/<процесс>.md` |
| «как **сделать**» (руками, с последствиями) | `docs/runbooks/<действие>.md` |
| «**почему** решили так» | `docs/adr/NNNN-<решение>.md` |
| «что это **слово** значит» | `docs/glossary.md` |
| «что **изменилось**» для пользователя | заголовок коммита и описание PR, не документ |
| «что делать **дальше**» | задача в `tasks/backlog/`, не документ |

Компас, когда непонятно: **читают подряд или сверяются?** Сверяются — `docs/reference/` или `docs/glossary.md`. **Делают по шагам или понимают?** Делают — runbook. Понимают — `docs/adr/` или `docs/flows/`.

## Шаг 3. Сколько

- **Шапка файла — до 10 строк.** Первый блок **выше кода**, и только он: его читают ДО кода, он ничего не рвёт. Импорты и директивы кодом не считаются. Отвечает на «что это и почему так устроено»; содержимое файла он не пересказывает.
- **Всё остальное в файле — максимум 3 строки.** Комментарий в теле, docstring — один на секцию кода. Отвечает только на то, чего не видно в коде: «сделано так, потому что», «работает только при», «здесь грабли».
- **Что режется без разговора.** Шапка, перечисляющая то, что видно в сигнатурах; локальный ченджлог («раньше было», «переименовано в TA-x») — это `git log`; список шагов, который и есть код ниже. Отвергнутый вариант ченджлогом не считается: «пробовали X, стоило Y» остаётся.
- Не влезло — заводи страницу в `docs/`, оставь в коде ссылку в одну строку.
- **Ссылка двусторонняя.** Комментарий даёт путь к документу, документ называет файлы, про которые он. Линтер проверяет обе стороны (`CMT003`, `MD004`).

Escape hatch: `docs-lint: allow` внутри блока. Он для случаев, где текст обязан стоять ровно здесь; обходить им требование сокращать нельзя.

## Шаг 4. Форма документа

Вторая строка любого дока в `docs/` — статус, дата, вердикт одним предложением:

```markdown
# Кэш свечей

> актуально · 2026-09-10 · свечи кэшируются на 5 минут по ключу asset+timeframe, снапшот расклада пишется отдельно и живёт вечно
```

Статусов ровно шесть, других нет:

| Статус | Значит |
| --- | --- |
| `актуально` | описывает работающий код, поддерживается |
| `реализовано` | решение в коде, документ заморожен |
| `справочник` | предметная область, не наш код; устаревает медленно |
| `черновик` | кода ещё нет, читать как замысел |
| `заморожено` | не поддерживается сознательно |
| `устарело` | врёт, читать нельзя; в той же строке ссылка на замену |

Правила формы:

- **Имя файла — это вопрос.** `candles.md` называет тему и не говорит, найду ли я там «как кэшируются» или «почему именно 1H». `candles-caching.md` говорит.
- **Каждая папка `docs/` имеет `README.md`** со строкой на документ: имя и на какой вопрос он отвечает. Без оглавления вики становится свалкой.
- **ADR не редактируют.** Передумали — новый ADR со ссылкой «Отменяет ADR-NNNN». Старый помечается `устарело`.
- **Секретов в тексте нет.**
- Термины бери из `docs/glossary.md` — там одно толкование на термин.

## Шаг 5. Нейминг: имя — это обещание

В имени стоит то, **что происходит**. Слой, тип и тема в имя не идут.

| Плохо | Почему | Хорошо |
| --- | --- | --- |
| `utils.ts`, `helpers.ts` | ничего не обещает | `slugify.ts`, `atr.ts` |
| `handleData()` | слой + тип | `mergeKlines()` |
| `ReadingManager` | «менеджер» — не действие | `ReadingTeardown` |
| `docs/cards.md` | тема, не вопрос | `docs/flows/card-to-candles.md` |

Тест: **имя обещает ровно то, что внутри, и ничего сверх?** Один термин — одно имя во всей кодбазе. Расхождения фиксируются в `docs/glossary.md`; на месте их не изобретают.

## Шаг 6. Перед тем, как закрыть задачу

**Доки, которые ты не трогал, могли начать врать.** Обязательный шаг:

```bash
npm run related
```

Команда выдаёт документы, говорящие о том же, что изменил PR. Открой каждый и ответь: **противоречит ли он тому, что я сделал?** Противоречит — правится в этом же PR. Устарел целиком — статус меняется на `устарело` со ссылкой на актуальный. Не про это — ничего.

Линтер найдёт мёртвую ссылку, но не найдёт двух документов, утверждающих разное. Это работа читателя.

## Проверка

| код | что |
| --- | --- |
| CMT001 | блок комментариев: шапка файла > 10 строк, в теле > 3 |
| CMT002 | то же для python-docstring |
| CMT003 | код ссылается на несуществующий документ |
| MD001 | markdown вне `docs/`, `tasks/` и `.claude/` |
| MD002 | док не вписан в README своей папки |
| MD003 | нет строки «статус · дата · вердикт» |
| MD004 | док ссылается на несуществующий путь |
| MD005 | PR тронул файлы, которые док зовёт своими, док не обновлён |
| LNG001 | кириллица в комментарии кода |
| NAM001 | имя файла или папки ничего не говорит |
