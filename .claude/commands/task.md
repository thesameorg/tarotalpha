Задачу **$1** ведёшь по `CLAUDE.md`. Расхождение — `CLAUDE.md` главнее. `#N` — issue GitHub: читай `gh issue view N`. Строка без номера — задача из беседы: issue не заводишь, оценка и отчёт идут в чат.

## 0. Своё место

`pnpm run wt <ветка>` под задачу, слагом по теме: issue «кэш свечей жжёт лимит» → `feat/candle-cache`.

## 1. Триаж — дёшево, до разведки

Четыре проверки: существует то, о чём она; не сделано попутно; нет дубля среди открытых issues (`gh issue list`); есть DoD. Мертва — закрыть с причиной: `gh issue close N --comment`. Устарела — переписать: `gh issue edit N --body`.

## 2. Разведка

Субагентом `recon` — `.claude/agents/recon.md`.

## 3. Оценка

«Как чиню», «Разведка», «Цена», «Что меняется», «DoD» — комментарием в issue (`gh issue comment N --body-file`), для задачи из беседы — сообщением в чат. Два экрана.

**Это и есть гейт-4:** показываешь оценку, а не пересказ. Дальше стоп: «да», «нет» или «не так». «Не так» — переигранный план, а не отменённая задача: возвращаешься к шагу 3.

## 5–7. Между гейтами

Вопросов не задаёшь. Код, тесты, `pnpm run check`, `pnpm run related`, критик, ветка, PR со строкой `Closes #N`, CI зелёный, DoD построчно. Две попытки на красное, потом стоп с текстом ошибки. Находки: сказать, мелкое чинить, дыру везде, issue на неподъёмное. Дерево после PR.

## Гейт «вижу»

- **PR.** Ссылка, CI зелёный.
- **Что меняется.** Первая строка PR.
- **DoD.** Строка из issue или из оценки, чем подтверждена.
- **Что ещё в PR.** Находки по дороге, по строке.
- **Что ушло из PR.** Отдельные PR и issues, по строке.
- **Смотреть здесь.** Куда ткнуть за минуту.

Мержит владелец. Дифф не читают. Issue закрывает мерж.
