Задачу **$1** ведёшь по `CLAUDE.md`. Расхождение — `CLAUDE.md` главнее. `#N` — issue GitHub: читай `gh issue view N`. Строка без номера — задача из беседы: issue не заводишь, след — PR.

На выходе готовый PR. Владельца по дороге не спрашиваешь: непонятное решаешь сам и называешь допущение в описании PR. Вопрос — только если при любой трактовке работа выйдет бессмысленной.

## 0. Своё место

`pnpm run wt <ветка>` под задачу, слагом по теме: issue «кэш свечей жжёт лимит» → `feat/candle-cache`.

## 1. Триаж — дёшево, до разведки

Четыре проверки: существует то, о чём она; не сделано попутно; нет дубля среди открытых issues (`gh issue list`); есть DoD. Мертва — закрыть с причиной: `gh issue close N --comment`. Устарела — переписать: `gh issue edit N --body`.

## 2. Разведка

Субагентом `recon` — `.claude/agents/recon.md`.

## 3. DoD

Одна проверяемая строка, до первой строки кода. Нет её в issue — пишешь сам и кладёшь строкой `DoD:` (`gh issue edit N --body`); у задачи из беседы держишь её при себе и повторяешь в описании PR.

## 4–6. Работа

Код, тесты, `pnpm run check`, `pnpm run related`, критик, ветка, PR со строкой `Closes #N`, CI зелёный, DoD построчно. Две попытки на красное, потом стоп с текстом ошибки. Находки: мелкое чинить тут же в этом PR, даже не по теме задачи, дыру везде, issue на неподъёмное; докладывать сразу и уже решённым, не вопросом. Дерево сносишь после PR.

## Что в описании PR

- **Что меняется.** Первая строка: что стало работать иначе.
- **DoD.** Строка задачи и чем подтверждена.
- **Допущения.** Что решил сам там, где задача молчала.
- **Что ещё в PR.** Находки по дороге, по строке.
- **Что ушло из PR.** Отдельные PR и issues, по строке.
- **Что уехало в `docs/`.** «Ничего» — валидный ответ.
- **Смотреть здесь.** Куда ткнуть за минуту.

Мержит владелец. Issue закрывает мерж.
