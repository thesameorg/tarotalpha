# TarotAlpha

Сайт с внешностью финтех-терминала, внутри — таро-расклад, который дорисовывает свечной график на сутки вперёд. Шутка держится на контрасте серьёзной подачи и абсурдного содержания. ТЗ целиком: `docs/idea.md`.

## Расклад детерминирован, и это задумано

Сид тасовки считается от инструмента, якоря, номера шага и версии движка. Якорь — время последней закрытой свечи, поэтому **окно фиксации равно таймфрейму**: на 1H расклад по одному инструменту один и тот же для всех, кто открыл его в течение часа, и меняется на границе следующей свечи.

Что из этого следует:

- «Расклад дня» — не отдельная механика, а следствие: одно окно, один расклад на всех.
- Дуэль двух пользователей на один инструмент внутри одного окна идёт только гадалками: карты у обоих одни и те же, а свечи и точность зависят от того, кого выбрали (`docs/adr/0006-readers-are-parallel-formulas.md`).
- «Переоткрыть расклад» и «второе мнение» внутри окна ничего не меняют: карты те же.

**Энтропия переключается окружением.** `SEED_ENTROPY=off` — детерминизм по окну, как описано выше. `SEED_ENTROPY=on` — в сид добавляется нонс самого расклада, карты у каждого свои, дуэль и переоткрытие начинают работать, а «Расклад дня» перестаёт быть общим и генерится отдельной задачей.

Воспроизводимость ссылки от режима не зависит: выпавшие карты и выбранная гадалка хранятся в самом раскладе, а свечи снапшотятся при создании. Энтропия влияет только на момент, когда расклад создаётся. Формулы движка правятся на месте, поэтому свечи прогноза по старой ссылке могут измениться после правки — карты и снапшот нет (`docs/adr/0005-engine-edited-in-place.md`).

## Команды

```bash
pnpm run dev              # клиент и воркер локально, docs/runbooks/run-locally.md
pnpm run test             # движок, биржевые адаптеры, воркер
pnpm run wt feat/foo   # дерево под задачу
pnpm run check            # политика документирования на изменённом
pnpm run check:all        # аудит всего репозитория
```
