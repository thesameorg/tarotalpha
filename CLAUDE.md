# CLAUDE.md

TarotAlpha: сайт с внешностью финтех-терминала, внутри — таро-расклад, который дорисовывает свечной график на сутки вперёд. Что строим: `docs/idea.md`. Как устроен расклад и почему он один на окно: `README.md`.

Этот файл всегда в контексте — здесь только карта и правила, остальное подтянется по ссылкам.

## Карта

| Папка | Что это |
| --- | --- |
| `docs/` | вики, оглавление в `docs/README.md` |
| `tasks/` | трекер: задача — файл, статус — папка |
| `scripts/` | оснастка: линтер политики документирования, деревья |
| `.claude/` | скилы, агенты, команды, хуки |
| `engine/` | движок прогноза: чистые формулы, версия — папка `engine/v1/`, старые не удаляются |
| `exchange/` | свечи с биржи: один код для браузера и воркера, без кэша |
| `web/` | клиент: Vite, vanilla TypeScript, Lightweight Charts |
| `worker/` | Cloudflare Worker: `/api/*`, мета-теги на `/r/:id`, статика |
| `migrations/` | SQL для D1 |

Один Worker со статикой, расклады в D1, свечи никто не хранит — почему так: `docs/adr/0001-cloudflare-worker-d1.md`.

## Порядок работы

Владельца спрашивают дважды за задачу — на шагах 4 и 8. Между ними идёт работа.

| Шаг | Кто | Что |
| --- | --- | --- |
| 1 | агент | **Триаж** — жива ли задача: есть предмет, не дубль, не сделана попутно, DoD проверяемый |
| 2 | агент | **Разведка** — субагентом `recon`, `.claude/agents/recon.md` |
| 3 | агент | **Оценка** — в файл задачи: как чиню, чем проверю, во что обойдётся, что пропускаю |
| **4** | **владелец** | **Гейт «делать»** — да, нет или не так |
| 5 | агент | Дерево, код, тесты, `npm run check` |
| 6 | агент | `npm run related`, ветка, пуш, PR, зелёный CI |
| 7 | агент | **Сборка** — находки разобраны, DoD сверен построчно, знание уехало в `docs/` |
| **8** | **владелец** | **Гейт «вижу»** — смотрит на работающее и мержит |

- **Гейт-4 — это файл задачи**, а не сообщение в чат: владелец читает `tasks/active/TA-NNN-*.md`.
- **«Не так» — переигранный план, а не отменённая задача.** Возвращайся к шагу 3 с новой вводной.
- **На гейте-8 дифф не читают.** Владелец смотрит на работающее и проверяет, то ли сделано.
- **Третий вопрос гейта-8: что уехало в `docs/`.** Почему — в `adr/`, устройство — в `flows/`, факт о чужой системе — в `reference/`. «Ничего» — валидный ответ и самый частый; пересказ диффа документом не становится.
- **Между гейтами вопросов не задаёшь.** Вопрос посередине означает, что разведка была плохая или на гейте-4 согласовали не то. Находки — не вопрос: о них докладывают сразу и работу не останавливают.
- **Две попытки на любое красное**, потом стоп и текст ошибки владельцу.
- **CI не узнаёт первым.** PostToolUse-хук показывает нарушение в момент правки, `pre-commit` держит формат и политику на коммите.
- **В `main` не пишет никто.** От него ветвятся и тянут, пушат в ветку, мержит владелец на гейте-8.
- **Соразмеряй проверки задаче.** Правка строки в документе не требует ни разведки, ни дерева, ни PR. Что пропустил — назови вслух и с причиной.

## Задача

Как заводится и что внутри — `tasks/README.md`. Здесь то, без чего не работает остальное:

- **Имя с первой секунды:** `TA-NNN` и слаг. Ветка — тем же слагом: `feat/candle-parser`. Совпали слаги — значит, двое делают одно.
- **DoD — одна проверяемая строка, до начала работы.** «Починить расклад» строкой не является. Нет DoD — есть пожелание, и на гейте-4 оно первым делом становится строкой.
- **Порядок задаёт блокировка, а не важность.** Что чему мешает — написано в самих файлах.

## Найденное по ходу дела

1. **Скажи сразу, как нашёл** — не списком в конце отчёта.
2. **Мелкое и связанное — в текущий PR, без вопросов.** Мелкое видно целиком в одном диффе и не тянет ни решения, ни нового поведения. Отдельным коммитом и отдельной строкой в описании PR.
3. **Дыру, потерю данных, утечку денег чини сразу**, независимо от размера. Не влезает — отдельный PR сегодня.
4. **Задачу заводи только на то, что руками сейчас не закрыть.** Обоснование предметное: работы на день, нужно решение владельца, нужен доступ. «Не просили» и «вдруг сломаю» обоснованием не считаются.

Решает тот, кто нашёл; владельцу это **сообщается**, а не выносится на голосование. «Нашёл, но без команды ничего не стал делать» отчётом не считается. Раздел сильнее любого правила про минимальный дифф: найденный баг чинится, даже если дифф от этого перестал быть минимальным.

## Параллельность

- **Одна задача — одна сессия — одно дерево.** `npm run wt -- feat/candle-parser` ветвится от свежего `origin/main` и ставит зависимости. В общем чекауте двое работают до первого `git add`.
- **Дерево сносишь сам, сразу после того как открыл PR:** `npm run wt:rm -- feat-candle-parser`. С незапушенным он откажется — так и задумано.
- **Субагентов зови за независимое:** разные подсистемы, разные оси поиска, разные линзы проверки. Пятеро на одном вопросе вернут один ответ за пятерых.

Роль живёт одним файлом в `.claude/agents/`: там и политика, и модель. Скилл с именем агента затеняется им и не грузится, поэтому одно имя — один файл. Модель на месте не выбирается. **Ниже Sonnet не спускаемся:** проверено на усушке этих же инструкций — мелкая модель режет правила вместе с обоснованиями и отдаёт текст, который выглядит короче, а работать по нему нельзя.

| Роль | Модель | Зачем |
| --- | --- | --- |
| сессия | Opus | гейты, решения, разбор находок |
| `recon` | Sonnet | читает тридцать файлов, отдаёт пять строк |
| `critic` | Sonnet | нужен вкус, но не решения |
| `lint-fixer` | Sonnet | механическая правка по коду ошибки линтера |

## Законы

Оба взяты из ТЗ, а не оплачены инцидентом. Третий появится после инцидента, а не из общих соображений.

1. **Ссылка на расклад воспроизводится вечно.** `engine_version` хранится рядом с раскладом, свечи снапшотятся при создании, старые версии движка не удаляются. → `docs/idea.md`, разделы 4 и 5.
2. **Рядом с каждой цифрой стоит дисклеймер.** Прогноз, точность, бэктест, индекс настроения читаются как аналитика. Это граница между шуткой и финансовой рекомендацией. → `docs/idea.md`, раздел 11.

## Документация

Шапка файла — до 10 строк, комментарий в теле — до 3. Не влезло — сначала спроси, нужно ли это вообще; нужно — страница в `docs/` и ссылка из кода. Ссылка двусторонняя, обе стороны проверяет линтер. Полная политика — `.claude/skills/documenting/SKILL.md`.

## Стиль

- **Код по-английски:** комментарии, имена, сообщения об ошибках. Держит `LNG001`, и только на строках, которые пишешь сейчас.
- **Русский живёт** в `docs/`, `tasks/`, оснастке `scripts/` и этом файле.
- **Русские данные остаются:** тексты арканов, толкования, контент — это данные, линтер строковых литералов не касается.
- **Строка — 120 символов, markdown не переносят вообще.** Абзац — одна строка. Держат форматтеры, не ревью.

## Как отвечать

- **Первая строка — вывод**, одним предложением. Разбор ниже, его читают по желанию.
- **Вывод про поведение, а не про код.** «Ссылка больше не тянет свечи заново» — вывод. «Вынес функцию в модуль» — дифф, ему место в «как чиню».
- **Имена бери из `docs/glossary.md`.**
- **Подробный ответ не сокращай до трёх строк.** Оценка, разбор находки и объяснение решения пишутся столько, сколько нужно, чтобы по ним действовать.

## Быстрые команды

```bash
npm run wt -- feat/candle-parser    # дерево под задачу: ветка от origin/main + зависимости
npm run wt:rm -- feat-candle-parser # снять своё дерево

npm run dev            # клиент и воркер с локальной D1, docs/runbooks/run-locally.md
npm run test           # движок, биржевые адаптеры, воркер
npm run deploy         # сборка и выкатка на workers.dev, docs/runbooks/deploy-workers-dev.md

npm run check          # политика документирования на изменённом
npm run check:all      # аудит всего репозитория
npm run related        # что перечитать на противоречия перед PR
npm run test:lint      # тесты самого линтера

pre-commit run --all-files   # формат и политика по всему репозиторию
```
