# CLAUDE.md

TarotAlpha: сайт с внешностью финтех-терминала, внутри — таро-расклад, который дорисовывает свечной график на сутки вперёд. Что строим: `docs/idea.md`. Как устроен расклад и почему у каждого свои карты: `README.md`.

Этот файл всегда в контексте — здесь только карта и правила, остальное подтянется по ссылкам.

## Карта

| Папка | Что это |
| --- | --- |
| `docs/` | вики, оглавление в `docs/README.md` |
| `scripts/` | оснастка: линтер политики документирования, деревья |
| `.claude/` | скилы, агенты, команды, хуки |
| `engine/` | движок прогноза: чистые формулы, правятся на месте; гадалок несколько, и каждая считает свои свечи по общим картам |
| `exchange/` | свечи с биржи: один код для браузера и воркера, без кэша |
| `web/` | клиент: Vite, vanilla TypeScript, Lightweight Charts; словари одиннадцати языков в `web/i18n/`; метод по-английски — `web/how.html`; внутри Telegram тот же сайт как мини-апп через `web/telegram.ts` |
| `worker/` | Cloudflare Worker: `/api/*`, мета-теги на `/r/:id`, статика; крон ведёт трек счёта и сверяет созревшее |
| `migrations/` | SQL для D1 |

Задачи живут в GitHub Issues репозитория, не в файлах. Один Worker со статикой, расклады в D1, свечи никто не хранит — почему так: `docs/architecture.md`.

## Порядок работы

Задача закинута — на выходе готовый PR. Владельца по дороге не спрашивают: он читает описание PR и мержит.

**Первым делом — путь по размеру.**

- **Короткий:** правка, `pnpm run check`, PR с DoD-строкой, зелёный CI. Разведки, критика, `related` и сборки нет, и пропуск их не объясняют. Так идёт всё, что не заводит нового поля, эндпоинта, таблицы или понятия и не трогает то, что хранит расклад, формулы гадалок, ману и запросы к бирже: текст, стили, вёрстка, доки, инструкции, конфиг, локальный фикс.
- **Полный:** всё остальное, по таблице ниже. Шаг, пропущенный на полном пути, называешь в PR с причиной.
- **Сомневаешься — короткий:** круг разведки и критика на мелочи стоит дороже того, что они там найдут.

| Шаг | Что |
| --- | --- |
| 1 | **Триаж** — жива ли задача: есть предмет, не дубль, не сделана попутно, DoD проверяемый |
| 2 | **Разведка** — субагентом `recon`, `.claude/agents/recon.md` |
| 3 | **DoD** — одна проверяемая строка, до первой строки кода |
| 4 | Дерево, код, тесты, `pnpm run check` |
| 5 | **Критик** — один проход, после его находок повторно не зовут; `pnpm run related`, ветка, пуш, PR со строкой `Closes #N`, зелёный CI |
| 6 | **Сборка** — находки разобраны, DoD сверен построчно, знание уехало в `docs/` |
| 7 | **Владелец** — читает готовый PR и мержит |

- **Вопрос владельцу — исключение.** Задаёшь, только если при любой трактовке работа выйдет бессмысленной. В остальных случаях выбираешь сам и называешь допущение в описании PR.
- **Находки — не вопрос:** мелкое чинят тут же, в текущем PR, и докладывают уже сделанным; работу не останавливают.
- **Описание PR читают вместо диффа.** Первая строка — что стало работать иначе. Ниже: допущения, находки по дороге, что уехало в `docs/`, куда ткнуть, чтобы увидеть работающее за минуту.
- **Что уехало в `docs/` — обязательная строка.** Устройство, «почему так», отвергнутое и факты о чужих системах — в док своей области (`docs/README.md`). «Ничего» — валидный ответ и самый частый; пересказ диффа документом не становится.
- **Две попытки на любое красное**, потом стоп и текст ошибки владельцу.
- **CI не узнаёт первым.** PostToolUse-хук показывает нарушение в момент правки, `pre-commit` держит формат и политику на коммите.
- **В `main` не пишет никто.** От него ветвятся и тянут, пушат в ветку, мержит владелец.

## Задача

Трекер — GitHub Issues этого репозитория: `gh issue list`, `gh issue view N`, `gh issue create`. Как заводится — `/task-new`, как ведётся — `/task`.

- **Небольшое и проговорённое в беседе — без issue.** След — PR. Issue заводит владелец руками или агент по прямому указанию, и дальше агент ведёт её по шагам выше.
- **Имя с первой секунды:** номер issue и слаг; у задачи из беседы — слаг по теме. Ветка — тем же слагом: `feat/candle-parser`. Совпали слаги — значит, двое делают одно.
- **DoD — одна проверяемая строка, до начала работы.** «Починить расклад» строкой не является. Нет DoD — есть пожелание, и строкой оно становится первым делом; в issue она стоит отдельной строкой `DoD:`.
- **Порядок задаёт блокировка, а не важность.** Что чему мешает — строка `blocked by #N` в самой issue.
- **В issue нет знания и прогресса.** Знание — в `docs/`, состояние — ветка и PR. Закрывает issue мерж PR со строкой `Closes #N`.

## Найденное по ходу дела

1. **Решаешь сразу, как нашёл, и докладываешь уже решённым** — не вопросом и не списком в конце отчёта. «Нашёл X, чиню здесь отдельным коммитом» — доклад. «Нашёл X, не знаю, как быть» и «могу поправить, если скажешь» — вопрос: решение вернулось владельцу.
2. **Мелкое — в текущий PR, без вопросов, даже если к задаче не относится.** Мелкое видно целиком в одном диффе и не тянет ни решения, ни нового поведения. Отдельным коммитом и отдельной строкой в описании PR.
3. **Дыру, потерю данных, утечку денег чини сразу**, независимо от размера. Не влезает — отдельный PR сегодня.
4. **Issue заводи только на то, что руками сейчас не закрыть.** Обоснование предметное: работы на день, нужно решение владельца, нужен доступ. «Не просили», «не по теме задачи» и «вдруг сломаю» обоснованием не считаются.

Решает тот, кто нашёл; владельцу это **сообщается**, а не выносится на голосование. «Нашёл, но без команды ничего не стал делать» отчётом не считается. Раздел сильнее любого правила про минимальный дифф: найденный баг чинится, даже если дифф от этого перестал быть минимальным.

## Параллельность

- **Одна задача — одна сессия — одно дерево.** `pnpm run wt feat/candle-parser` ветвится от свежего `origin/main` и ставит зависимости. В общем чекауте двое работают до первого `git add`.
- **Дерево сносишь сам, сразу после того как открыл PR:** `pnpm run wt:rm feat-candle-parser`. С незапушенным он откажется — так и задумано.
- **Субагентов зови за независимое:** разные подсистемы, разные оси поиска, разные линзы проверки. Пятеро на одном вопросе вернут один ответ за пятерых.

Роль живёт одним файлом в `.claude/agents/`: там и политика, и модель. Скилл с именем агента затеняется им и не грузится, поэтому одно имя — один файл. Модель на месте не выбирается. **Ниже Sonnet не спускаемся:** проверено на усушке этих же инструкций — мелкая модель режет правила вместе с обоснованиями и отдаёт текст, который выглядит короче, а работать по нему нельзя.

| Роль | Модель | Зачем |
| --- | --- | --- |
| сессия | Opus | решения, разбор находок, сборка |
| `recon` | Sonnet | читает тридцать файлов, отдаёт пять строк |
| `critic` | Sonnet | нужен вкус, но не решения |
| `lint-fixer` | Sonnet | механическая правка по коду ошибки линтера |

## Закон

Закон один, взят из ТЗ, а не оплачен инцидентом. Второй появится после инцидента, а не из общих соображений.

1. **На каждом экране с цифрой есть дисклеймер — один, в подвале.** Прогноз, точность, итог дня, бэктест, индекс настроения читаются как аналитика. Это граница между шуткой и финансовой рекомендацией. У каждого числа её не повторяют: одна фраза четыре раза на экран читается как шум, и глаз перестаёт её видеть. Подвал не прилипает к низу экрана: на телефоне он съел бы высоту, которой не хватает графику и картам. → `docs/idea.md`, раздел 11.

Ссылка не обещает тех же свечей навсегда: формулы правятся на месте, ссылка хранит карты, снапшот и гадалку, а свечи по ней считает текущая формула этой гадалки — `docs/engine.md`.

## Документация

- **Документ описывает «сейчас».** Не историю («раньше было») и не планы («будет»): история — `git log`, планы — issues. Док, который врёт про текущее состояние, чинится в том же PR, который его состарил.
- Шапка файла — до 10 строк, комментарий в теле — до 3. Не влезло — сначала спроси, нужно ли это вообще; нужно — страница в `docs/` и ссылка из кода. Ссылка двусторонняя, обе стороны проверяет линтер. Полная политика — `.claude/skills/documenting/SKILL.md`.

## Стиль

- **Код по-английски:** комментарии, имена, сообщения об ошибках. Держит `LNG001`.
- **Русский живёт** в `docs/`, issues, оснастке `scripts/` и этом файле.
- **Русские данные остаются:** тексты арканов, толкования, словари `web/i18n/` — это данные, линтер строковых литералов не касается.
- **Строка — 120 символов, markdown не переносят вообще.** Абзац — одна строка. Держат форматтеры, не ревью.

## Как отвечать

- **Первая строка — вывод**, одним предложением. Разбор ниже, его читают по желанию.
- **Вывод про поведение, а не про код.** «Ссылка больше не тянет свечи заново» — вывод. «Вынес функцию в модуль» — дифф, ему место в «как чиню».
- **Имена бери из `docs/glossary.md`.**
- **Подробный ответ не сокращай до трёх строк.** Оценка, разбор находки и объяснение решения пишутся столько, сколько нужно, чтобы по ним действовать.

## Быстрые команды

```bash
pnpm run wt feat/candle-parser    # дерево под задачу: ветка от origin/main + зависимости
pnpm run wt:rm feat-candle-parser # снять своё дерево

gh issue list           # что в работе; gh issue view N — одна задача
pnpm run dev            # клиент и воркер с локальной D1, docs/architecture.md
pnpm run test           # движок, биржевые адаптеры, воркер
pnpm run deploy         # аварийная выкатка с машины; обычная — мерж в main, docs/architecture.md

pnpm run check          # политика документирования по всему репозиторию плюс доки, отставшие от PR
pnpm run check:all      # то же без сверки с PR — ровно то, что гоняет CI
pnpm run related        # что перечитать на противоречия перед PR
pnpm run test:lint      # тесты самого линтера

pre-commit run --all-files   # формат и политика по всему репозиторию
```
