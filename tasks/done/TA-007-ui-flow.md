# TA-007 · Вёрстка и юзер-флоу

> ветка: feat/prototype · PR: нет

**Зачем.** ТЗ описывает флоу словами: лендинг, прорисовка графика, три шага расклада, пейвол, шаринг. Экранов нет, состояний нет, мобильной раскладки нет — а 70 % шеров придут из телеги, то есть с телефона.

**Что меняется.** Флоу перестаёт быть текстом и становится набором экранов с состояниями, включая пустое, загрузку и отказ провайдера котировок.

**DoD.** Каждый экран из `docs/idea.md` существует в двух раскладках и имеет состояние на случай, когда свечи не пришли.

**Как чиню.** Переношу `tarot-alpha.html` в `web/` как есть по визуалу: стили, анимации карт и графика, пейвол, футер. Меняю то, чего в HTML не было: клиент не считает расклад, а ходит в `/api/*` (`docs/flows/reading-lifecycle.md`); «Поделиться» отдаёт ссылку `/r/:id`, а не код; страница ссылки с «Воспроизвести», «Свой расклад» и бейджем проверки пророчества; состояния 400/429/502/404 текстом, не пустым графиком; выдуманные цифры бэктеста из футера убраны до настоящего бэктеста — закон 2. Звук и Lottie не делаю.

**Разведка.** Переиспользую: разметку, CSS и канвас-рендер из `tarot-alpha.html`. Завожу новое: роутер на два маршрута, клиент API, страница расклада. Сломается: ничего. Не трогаю: `lightweight-charts` из ТЗ — канвас из HTML уже умеет зону прогноза и анимацию, библиотека ради прототипа не нужна. Пропустил: «История».

**Цена.** Ноль внешних вызовов; в dev свечи идут через воркер.
