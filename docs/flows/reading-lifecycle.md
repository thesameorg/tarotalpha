# Жизнь расклада: что создаётся когда, что хранится, кто читает

> актуально · 2026-09-10 · свечи берёт браузер прямо с биржи, шаги считает движок в браузере, воркер пишет расклад только по «Поделиться» и снимает снапшот сам; ссылка читает снапшот и считает свечи текущим движком, а реальные свечи для проверки снова берёт браузер

Свечи не хранятся нигде, кроме снапшота внутри расклада: ни кэша, ни инджеста, ни cron. Один и тот же движок `engine/` работает в браузере и в воркере. При `SEED_ENTROPY=off` карты и свечи выводятся из четвёрки `asset`, `anchor_ts`, `step`, `engine_version`, поэтому воркер при записи клиенту не верит, а пересчитывает сам. Движок один и правится на месте: ссылка хранит карты и снапшот, свечи по ней считаются текущими формулами — `docs/adr/0005-engine-edited-in-place.md`. Формулы — `card-to-candles.md`, свечи — `candles-from-exchange.md`.

## Последовательность

| Шаг пользователя | Кто и что делает | Событие |
| --- | --- | --- |
| открыл страницу или выбрал инструмент в шапке графика | браузер: 168 закрытых свечей с биржи через `exchange/`, якорь, ATR, график; без клика грузится инструмент из `?asset=`, иначе последний выбранный из `localStorage`, иначе `BTCUSDT` | `chart_loaded`, шлёт клиент |
| «Открыть расклад · день N» | браузер: `computeSteps` из `engine/`; в полноэкранном вскрытии пользователь вытягивает три карты из веера рубашек, i-я вытянутая открывает i-ю карту шага — выбор ни на что не влияет: карты заданы сидом, веер — театр; после третьей — анимация 24 свечей; «закрыть» до третьей — шаг не открыт, события нет; N > 2 — пейвол, без запросов | `step_opened`, шлёт клиент |
| «Поделиться» | `POST /api/readings` с `{asset, anchor_ts, steps, source, engine_version}` → воркер сам берёт свечи по якорю у провайдера автора, а если тот недоступен с края Cloudflare — у следующего, и пишет фактический в `source`; считает шаги тем же движком, пишет строку, отдаёт `{id, url}`. Метка движка не совпала с серверной — 409 `engine_mismatch`: вкладка со старым бандлом показала одни карты, а сервер записал бы другие. Ссылка в окне «Поделиться» несёт язык автора: `/r/:id?lang=ru` | `shared`, пишет воркер; биржа недоступна — `share_failed` |
| открыл `/r/:id` | воркер отдаёт `index.html` из статики с вписанными `<html lang>`, `og:title`, `og:description`, `og:url` на языке ссылки (`?lang`), иначе первом подходящем из `Accept-Language`, иначе английском; языки — `web/i18n/langs.ts` — краулер телеги JS не выполняет, поэтому `/r/*` и `/api/*` идут в воркер раньше статики (`run_worker_first`); браузер: `GET /api/readings/:id` → снапшот, карты, `source`; шаги пересчитывает текущим движком; реальные свечи после якоря берёт у биржи сам и считает точность | ничего: просмотр — факт аналитики, он остаётся в логах Workers (observability включена в `wrangler.jsonc`), в D1 на чтении не пишется ни строки |
| упёрся в пейвол; «Свой расклад» или другой инструмент в шапке ссылки; «Воспроизвести» | `POST /api/events` | `paywall_hit`, `own_reading_clicked`, `replayed` |

Снапшот при записи равен тому, что видел автор: закрытые свечи по якорю не меняются, незакрытую в снапшот не берут; сменился провайдер — расходятся сотые доли процента, карты те же. Ошибки записи: неизвестный инструмент — 400 `unknown_asset`, якорь старше, чем отдаёт биржа, — 422 `too_old`, биржа недоступна воркеру — 502 `unavailable`, невалидное поле — 400 `bad_request` с именем поля, третий шаг — 402 `paywall`: бесплатных шагов два. Расклад при любой из них не пишется.

## Что хранится

Одна таблица `readings` и журнал `events`, схема — `migrations/0001-readings-and-events.sql`.

| Поле `readings` | Что |
| --- | --- |
| `id` | 8 символов без гласных и похожих знаков, случайный; коллизия — повтор |
| `asset`, `timeframe`, `anchor_ts`, `source` | инструмент, `1H`, якорь в ms UTC, провайдер снапшота |
| `engine_version`, `seed_nonce` | метка формул, которыми расклад создан, видна в панели `tech`; нонс `NULL` при `SEED_ENTROPY=off` |
| `steps` | JSON `[[[card_id, reversed] × 3] …]` по шагам |
| `candles_snapshot` | JSON `[[t, o, h, l, c] …]`, 168 свечей |
| `created_at` | когда записан |

Всё остальное вычислимо и в ответе `GET /api/readings/:id` не дублируется: прогноз, толкования, итог дня и точность браузер считает текущим движком. Инвариант: снапшот и карты после записи не меняются никогда; что из них рисуется — дело формул на момент просмотра.

`events`: `ts`, `type`, `asset`, `reading_id`, `step`, `ip_hash`. Это воронка, а не аналитика: строка на событие, индекс по `(ts, type)`, читает её только владелец руками.

## Лимиты и отказы

- Все `/api/*` под лимитом по IP: binding Rate Limiting Cloudflare, 60 запросов в минуту, окно по стенным часам, работает и локально; ответ 429 с `Retry-After`. Обвязка — `worker/rate-limit.ts`.
- Пользователь всегда видит состояние, а не пустой график: биржа недоступна из браузера — «Биржа не отвечает из вашей сети» и повтор; неизвестный инструмент — «Такого инструмента нет на бирже»; 502 на «Поделиться» — «Не удалось снять снапшот, повторите»; 429 — «Слишком много запросов»; 404 на ссылке — «Расклад не найден» и кнопка «Свой расклад».
