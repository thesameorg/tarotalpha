# Как устроен и выкатывается сайт

> актуально · 2026-09-12 · один Cloudflare Worker отдаёт статику и `/api/*`, расклады лежат в D1, свечи не хранит никто; движок один на браузер и воркер; проверки идут на PR, прод обновляется из Actions на пуш в `main`

## Кто с кем говорит

| Кто | С кем | Зачем |
| --- | --- | --- |
| браузер | биржа: Bybit, затем Binance (`exchange.md`) | 168 свечей для графика, реальные свечи для проверки пророчества |
| браузер | воркер, `/api/*` | записать и дорастить расклад, прочитать ссылку, события воронки, рейтинг гадалок |
| воркер | биржа | снапшот при первом открытом дне, свечи для трека счёта и его сверки |
| воркер | D1 | строки раскладов и журнал событий |
| крон, каждые 10 минут | воркер, `scheduled` | сверка созревших раскладов счёта и дорисовка трека (`reading-lifecycle.md`) |
| Telegram | тот же сайт | мини-апп без участия сервера (`telegram.md`) |

Воркер отдаёт SPA из static assets. `/api/*` и `/r/*` идут в него раньше статики (`run_worker_first`): иначе SPA-фолбэк ответил бы на `/r/<id>` голым `index.html`, а краулер превью JS не выполняет, и мета-теги ссылки пишет воркер. Статика скрипт не запускает и CPU не тратит.

## Код

| Папка | Что там |
| --- | --- |
| `engine/` | движок прогноза: чистый TypeScript без I/O и импортов платформы, собирается и в бандл страницы, и в воркер (`engine.md`) |
| `exchange/` | запросы к биржам за закрытыми свечами, один код для браузера и воркера (`exchange.md`) |
| `web/` | клиент и корень Vite: `index.html`, `how.html` — метод по-английски, стили, код страницы, словари в `web/i18n/` |
| `worker/` | обработчик `fetch` и `scheduled`, маршруты `/api/*`, доступ к D1 |
| `migrations/` | SQL для D1, применяет `wrangler d1 migrations apply` |
| `scripts/` | линтер политики документирования, деревья под задачи |
| `.github/` | CI и деплой |

Один `package.json`, без воркспейсов; пакеты ставит pnpm. Vite с `@cloudflare/vite-plugin`: `vite dev` поднимает клиент и воркер с локальной D1 одним процессом, `vite build` собирает оба, `wrangler deploy` выкатывает собранный конфиг. Vanilla TypeScript без фреймворка, график — Lightweight Charts.

## Почему так

- **Один Worker, не Pages.** Cloudflare ведёт новые проекты на Workers со статикой. Pages плюс отдельный Worker — два деплоя и без своего домена два origin'а (`pages.dev` и `workers.dev`): CORS, разные куки и логи; CPU у Pages Functions тот же, это те же Workers.
- **Свечи не хранятся.** Браузер берёт свечи у биржи сам, движок считает дни в браузере; воркер ходит в биржу раз на расклад — снять снапшот, чтобы в базе лежало то, что снял он, а не прислал клиент. Ни KV, ни инджеста, ни таблицы котировок. Лимит биржи считается по IP, и у воркера это общий IP колокации: биржа начнёт отвечать воркеру 429 — это видно по событию `share_failed`.
- **D1 под расклады.** Строка около 10 КБ, почти всё — снапшот. Читается только по `id` и по треку счёта.
- **`account_id` прибит в `wrangler.jsonc`:** в wrangler залогинено два аккаунта, деплой не должен уехать в чужой.
- **Рантайм — Workers, не Node:** нет `fs` и долгих процессов, запрос к бирже уходит из колокации рядом с пользователем. Тесты воркера идут внутри workerd (`@cloudflare/vitest-plugin`), а не на моках Node.
- **Отвергнуто:** Vercel с Neon Postgres — два провайдера, холодные старты, статика и база в разных местах; VPS с Node и SQLite — деплой, бэкапы и мониторинг руками у единственного разработчика; кэш свечей в KV — снимает лимит биржи по IP, но бесплатный KV даёт 1 000 записей в день, а воркер и так ходит в биржу раз на расклад; TradingView как источник свечей — виджет это iframe без API, из него не прочитать свечи и на нём не дорисовать прогноз.

## Лимиты

| Ресурс | Бесплатно | Workers Paid, $5/мес | Что нам |
| --- | --- | --- | --- |
| CPU на вызов | 10 мс | 30 с | расклад на семь дней любой гадалкой — до половины миллисекунды, сверка всего стола — около миллисекунды (`engine/cpu-budget.test.ts` держит потолок 5 мс); крон живёт в тех же 10 мс, отсюда пять сверок и три слота за прогон; OG-картинка через satori и resvg стоит десятки-сотни мс и в бесплатный план не влезает, её нет |
| D1 | 500 МБ, 100 тыс. записей в день | 10 ГБ, 50 млн записей в месяц | около 50 тысяч раскладов на бесплатном; пишут первый день, доращивание, события и крон, чтение ссылки не пишет ничего — просмотры считает observability Workers |
| запросы к воркеру | 100 тыс. в день | 10 млн в месяц | статика не считается |
| Cache API | на `workers.dev` не работает |  | до своего домена кэшировать нечем |

- Все `/api/*` под лимитом 60 запросов в минуту на IP (Rate Limiting binding, `worker/rate-limit.ts`). Считает каждая точка присутствия Cloudflare отдельно, окно по стенным часам. Лимит бережёт D1 от скрейпера, но не дневную квоту запросов: вызов воркера засчитан раньше, чем он спросил лимитер.
- Живой расход CPU — дашборд Workers → Observability, поле `cpuTime` у `POST /api/readings`.

## Проверки

| Где | Что гоняется |
| --- | --- |
| PostToolUse-хук на правку агента | политика документирования на записанном файле целиком |
| `pre-commit` на коммит | формат, shellcheck, eslint и `tsc` на застейдженном; полный аудит `scripts/docs_lint.py` — та же команда, что в CI |
| `pnpm run check` | полный аудит плюс предупреждения о доках, отставших от диффа против `origin/main` |
| Actions, job `check`, только `pull_request` | `pnpm install --frozen-lockfile`, typecheck, lint, test, build, `prettier --check`, аудит `scripts/docs_lint.py` и его тесты |
| Actions, job `deploy`, пуш в `main` и ручной запуск | миграции D1, `pnpm run deploy`, `curl /api/health` снаружи |
| нигде | e2e в браузере, нагрузочные: работающее смотрит владелец |

- **Линтер документации не прощает ничего.** Каждый слой ругается на всё, что видит, без поправки на авторство строк: иначе CI узнаёт первым. Шапка, выросшая с 10 строк до 11 правкой одной строки, прошла бы хук, смотрящий только дифф; ссылка из нетронутого дока на переименованный файл прошла бы `pre-commit`, смотрящий только застейдженное. Хук `docs-lint` в `pre-commit` — `pass_filenames: false` и `always_run: true`, иначе коммит из одного удаления до него не доходит; что команда та же, что в CI, держит `scripts/test_docs_lint.py`.
- Отвергнуто для линтера: доля строк плюс долг по состоянию базы — механизм ради долга, которого нет; диффовый режим, который помнит удалённые пути, — новый механизм под одно правило; CI с ратчетом — долг в `main` становится возможным.
- Цена: коммит, ломающий ссылку в чужом файле, не пройдёт, даже если её чинит следующий, — правка ссылки едет вместе с переименованием. Полный аудит стоит около 0,15 с на коммит.
- **Проверки на `main` не повторяются:** туда попадает только проверенная ветка. Merge-коммит отличается от головы PR, если `main` успел уехать, и такой код уйдёт на прод непроверенным; страховка — правило защиты ветки «Require branches to be up to date before merging», его включает владелец. `pnpm run build` в `deploy` — единственная проверка на `main`.
- Отвергнуто: без CI вовсе — `pre-commit` обходится флагом и сборку целиком не гоняет, а Actions на этом репозитории бесплатны.

## Выкатка

Обычный путь — смержить зелёный PR в `main`. Job `deploy` в `.github/workflows/check.yml` применяет миграции, выкатывает и дёргает `/api/health` снаружи.

- **Секрет один:** `CLOUDFLARE_API_TOKEN` в секретах репозитория GitHub; `account_id` не секрет и лежит в `wrangler.jsonc`. Без секрета шаг деплоя пропускается молча и прод остаётся прежним: мерж не краснеет по причине, не связанной с кодом.
- **Миграции идут перед деплоем.** Добавляющая миграция безопасна: воркер со старой схемой переживает новую колонку, а наоборот — падает. Снос колонки стоит секунд: между миграцией и выкаткой старый воркер пишет в колонку, которой уже нет, и записи раскладов в это окно отказывают. Так снесли `engine_version`: на прототипе без трафика это дешевле, чем перестраивать таблицу ради колонки, которую никто не читает. Схему назад не откатывают.
- **Красный `deploy` при зелёном PR** — прод остаётся на предыдущей версии, лечит следующий PR.
- Отвергнуто: деплой руками с машины — токена в GitHub нет, но прод привязан к одной машине и одному человеку; `wrangler-action` — тот же wrangler в обёртке, а своя команда деплоя уже собирает клиент и берёт конфиг из `web/dist`.
- Цена: токен с правами на Workers и D1 лежит в GitHub — второй канал доступа к аккаунту.

**Завести секрет — один раз, делает владелец.**

1. Cloudflare → My Profile → API Tokens → Create Token → шаблон «Edit Cloudflare Workers», к правам добавить `Account · D1 · Edit`. Account Resources — только `Dksg87@gmail.com's Account`.
2. `gh secret set CLOUDFLARE_API_TOKEN --repo thesameorg/tarotalpha` и вставить значение в приглашение. Ни в файлы, ни в чат токен не вставлять. Ротация — так же: новый токен в дашборде, затем `gh secret set`.
3. Следующий пуш в `main` — job `deploy` зелёный, в `wrangler deployments list` новая версия.

**Аварийно, с машины** — секрет отозван, Actions лежит, нужен откат.

1. `wrangler whoami` — в списке `Dksg87@gmail.com's Account`, в правах `d1 (write)`. Нет — `wrangler login`.
2. Новая миграция в `migrations/` — сначала `pnpm exec wrangler d1 migrations apply tarotalpha --remote`, потом деплой.
3. `pnpm run deploy` — `vite build`, затем `wrangler deploy` по собранному конфигу; в конце печатает `https://tarotalpha.dksg87.workers.dev`.
4. `curl https://tarotalpha.dksg87.workers.dev/api/health` → `{"ok":true}`; открыть `/?asset=BTCUSDT`, открыть день, «Поделиться», открыть ссылку в другом окне.

Откат — `pnpm exec wrangler rollback`, возвращает предыдущую версию воркера. База D1 `tarotalpha` пайплайном не создаётся: она заведена `pnpm exec wrangler d1 create tarotalpha`, id — в `wrangler.jsonc`. Превью-версия для Telegram — `pnpm run deploy:tg`, ходит в ту же D1, что и прод (`telegram.md`).

## Локально

1. `pnpm install --frozen-lockfile` — Node 22+. `packageManager` в `package.json` держит версию pnpm; нет pnpm — `corepack enable`. Стор один на машину, в каждом дереве задачи — жёсткие ссылки.
2. `pnpm exec wrangler d1 migrations apply tarotalpha --local` — схема в локальную D1 (`.wrangler/state`, тот же каталог читает `vite dev`).
3. `pnpm run dev` — клиент и воркер на `http://localhost:5173`; `/api/health` отвечает `{"ok":true}`.
4. `http://localhost:5173/?asset=BTCUSDT` — график грузится живым запросом из браузера к бирже; биржа недоступна из сети — страница скажет об этом.

`pnpm run test` — движок, биржевые адаптеры на моках и воркер внутри workerd. Весь прогон CI с тем, чего CI не смотрит, — команда `/check`.
