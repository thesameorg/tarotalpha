# Свечи с бирж: откуда, какие и почему их никто не хранит

> актуально · 2026-09-12 · браузер и воркер берут закрытые часовые свечи прямо у биржи одним запросом по якорю; первым идёт Bybit, потому что Binance не отвечает с края Cloudflare; хранится только снапшот внутри расклада, кэша и инджеста нет

Код один для браузера и воркера — `exchange/`. Ответ биржи нормализуется в `{t, o, h, l, c}`, `t` — открытие в ms UTC.

## Какие свечи берём

- **Якорь** — `anchor_ts = floor(now / 1ч) · 1ч − 1ч`, время открытия последней закрытой свечи. Незакрытую не берём: она меняется внутри часа, а снапшот должен быть одинаков у всех, кто открыл расклад в этом окне.
- **Снапшот** — 168 свечей с `endTime = anchor_ts + 1ч − 1`. Для якоря в прошлом запрос тот же и свечи те же, поэтому воркер при записи получает ровно то, что видел автор, не получая свечи от него. Меньше 168 свечей или последняя не на якоре — `too_old`, расклад не пишется.
- **Реальные свечи** для проверки пророчества — `startTime = anchor_ts + 1ч`, не больше `24 · дней`, только закрытые. Их берёт браузер при открытии ссылки, у той же биржи, что и снапшот, иначе точность считалась бы между двумя биржами. Сервер их не хранит: итог считается заново на каждом просмотре, это один запрос с IP зрителя.
- **Инструмент** проверяется маской `^[A-Z0-9]{2,20}$`, существование — биржей: её «неизвестный символ» — наш `unknown_asset`. В браузере это умеет только Bybit: 400 Binance приходит без CORS-заголовков, и браузер видит сетевой отказ, а не код. Акций и форекса нет: провайдеры платные, ключей нет.

## Очередь бирж

- Bybit, затем Binance. Binance и его зеркало `data-api.binance.vision` отвечают 403 на запросы с IP Cloudflare (HTML-страница WAF, проверено через `wrangler dev --remote`), а Bybit отвечает и браузеру, и воркеру.
- Следующую биржу спрашивают, если предыдущая отказала, ответила не JSON или молчит дольше восьми секунд: зависшая иначе держала бы очередь вечно. Отказ «такого символа нет» сильнее отказа «не ответил», в каком бы порядке они ни пришли.
- Биржа снапшота пишется в расклад полем `source`. Воркер при записи сначала спрашивает биржу автора, недоступна с края — следующую, и пишет фактическую: карты от свечей не зависят, а часовые свечи двух бирж расходятся на сотые доли процента. Недоступны обе — 502 и «повторить».
- Геоблок: обе биржи закрыты для части регионов (США — 403 и 451). В браузере это IP пользователя, и цепочка уходит к следующей бирже.
- Лимиты бирж считаются по IP. В браузере это IP пользователя, в воркере — общий IP колокации Cloudflare, поэтому воркер ходит в биржу раз на расклад: при первом открытом дне и в крон. Кэша нет; биржа начнёт отвечать воркеру 429 — это видно по событию `share_failed`.

## Bybit: `GET /v5/market/kline`

Проверено живыми запросами 2026-09-10 и по документации API v5 (bybit-exchange.github.io).

- `https://api.bybit.com/v5/market/kline?category=spot&symbol=BTCUSDT&interval=60&limit=168&end=<anchor_ts + 3600000 − 1>`; для свечей после якоря — `start`. `interval` — минуты (`60`), не `1h`; без `category` подразумевается `linear` (фьючерсы).
- `limit` по умолчанию 200, максимум 1000: `limit=1001` молча отдаёт 1000. `end` включает свечу, открытую на якоре.
- Ответ: `{"retCode":0,"retMsg":"OK","result":{"category","symbol","list":[…]}}`; элемент `list` — `[startTime, open, high, low, close, volume, turnover]`, всё строками, включая время. **Список идёт от новых к старым**, `exchange/bybit.ts` его разворачивает.
- Ошибки приходят с HTTP 200: неизвестный символ — `retCode: 10001` «Not supported symbols» (общий «ошибка параметра»); `10006` — лимит эндпоинта; `10009` — «Service Restricted», регион не обслуживается. С IP из США документация обещает HTTP 403 ещё до `retCode`.
- Лимит: 600 запросов за 5 секунд на IP; превышение — HTTP 403 «access too frequent» и бан IP минимум на 10 минут. Заголовков `X-Bapi-Limit*` публичный kline не присылает.

## Binance: `GET /api/v3/klines`

Проверено живыми запросами 2026-09-10 и по документации Spot REST API (developers.binance.com).

- `https://api.binance.com/api/v3/klines?symbol=BTCUSDT&interval=1h&limit=168&endTime=<anchor_ts + 3600000 − 1>`; для свечей после якоря — `startTime`. Без `endTime` последняя строка — незакрытая свеча текущего часа.
- `limit` по умолчанию 500, максимум 1000: `limit=2000` молча отдаёт 1000.
- Ответ: массив строк по 12 позиций — `[openTime, open, high, low, close, volume, closeTime, quoteVolume, trades, takerBuyBase, takerBuyQuote, ignore]`; цены и объёмы строками, время числами, от старых к новым.
- Вес запроса 2 при любом `limit`, бюджет IP — 6000 веса в минуту (`x-mbx-used-weight-1m` в ответе): браузеру это тысячи запросов в минуту. 429 — лимит превышен; 418 — IP забанен за запросы после 429, от 2 минут до 3 дней; 403 — сработал WAF.
- Неизвестный символ — HTTP 400 `{"code":-1121,"msg":"Invalid symbol."}` без CORS-заголовков. Геоблок — HTTP 451 `{"code":0,"msg":"Service unavailable from a restricted location…"}`; в документации не описан, известен по отчётам пользователей.
