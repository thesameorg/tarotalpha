# ADR-0004 · Проверки гоняются только на PR, деплой с `main` идёт без повторного прогона

> реализовано · 2026-09-10 · job `check` запускается только на `pull_request`; пуш в `main` сразу применяет миграции и деплоит; отменяет ADR-0003 в части «пуш в main — те же проверки»

Отменяет ADR-0003 в одной строке таблицы; всё остальное из него в силе.

## Контекст

На мерже проверки шли второй раз — те же полминуты, что на PR. Владелец решил, что в `main` попадает только проверенная ветка, и повторный прогон не нужен.

## Решение

| Где | Что гоняется |
| --- | --- |
| Actions, job `check`, только `pull_request` | `pnpm install`, `typecheck`, `lint`, `test`, `build`, `prettier --check`, аудит `scripts/docs_lint.py` и его тесты |
| Actions, job `deploy`, пуш в `main` и ручной запуск | `wrangler d1 migrations apply --remote`, `pnpm run deploy`, `curl /api/health` |

## Цена

Merge-коммит отличается от головы PR, если `main` успел уехать: такой код никто не проверял, и он уедет на прод. Страховка — правило защиты ветки «Require branches to be up to date before merging» в настройках репозитория GitHub, его включает владелец; тогда каждый PR перед мержем обновляется до `main` и проверяется заново.

## Последствия

- Красный деплой при зелёном PR теперь возможен, если сборка сломана merge-коммитом; прод остаётся на предыдущей версии, лечится следующим PR.
- `pnpm run build` в `deploy` остаётся единственной проверкой на `main`.
