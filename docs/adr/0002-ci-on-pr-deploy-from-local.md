# ADR-0002 · Проверки гоняет GitHub Actions на PR, деплой идёт с машины разработчика

> устарело · 2026-09-10 · отменён `0003-deploy-from-actions-on-main.md`: деплой идёт из Actions на пуш в `main`; таблица проверок перенесена туда без изменений

## Контекст

Разработчик один, всё можно катить с машины. Но порядок работы требует зелёного CI перед гейтом «вижу», а `pre-commit` проверяет только застейдженное и молчит про сборку целиком.

## Решение

| Где | Что гоняется |
| --- | --- |
| `pre-commit` на коммит | формат, eslint и `tsc` на застейдженном, политика документирования на изменённых строках |
| Actions на PR и на пуш в `main` | `npm ci`, `typecheck`, `lint`, `test`, `build`, `prettier --check`, полный аудит `scripts/docs_lint.py` и его тесты |
| нигде | деплой, e2e в браузере, нагрузочные |

- **Деплой с локалки.** `npm run deploy` под учёткой владельца. Ключ Cloudflare в секретах Actions не лежит: это второй канал доступа к аккаунту ради экономии одной команды.
- **E2E не гоняется.** Гейт «вижу» — владелец смотрит на работающее руками; автоматический браузерный прогон появится, когда его отсутствие оплатится инцидентом.
- **Пуш в `main` — те же проверки, что на PR.** Мерж без PR запрещён процессом, а не веткой; проверка на `main` — страховка от него.

## Альтернативы

- **Деплой из Actions на мерж.** Автоматичнее, но требует токена в GitHub и разводит «что задеплоено» с «что в `main`» при красном деплое. Вернуться к этому, когда разработчиков станет двое.
- **Без CI вовсе.** `pre-commit` обходится флагом, и `npm run build` целиком там не гоняется. Отказ ничего не стоит: Actions на пустом репозитории бесплатны.

## Последствия

Файл — `.github/workflows/check.yml`. Красный CI на PR — стоп по правилу «две попытки», потом текст ошибки владельцу.
