# ADR-0001 · Один Cloudflare Worker, D1 под расклады, свечи с биржи без кэша

> реализовано · 2026-09-10 · прототип живёт в одном воркере со статикой и раскладами в D1; свечи никто не хранит и не кэширует — они лежат только снапшотом внутри расклада; сборка через Vite с плагином Cloudflare, без воркспейсов

## Контекст

Проект — статическая страница плюс маленький бэк: записать расклад, отдать его по короткой ссылке, вписать мета-теги для превью. Разработчик один, аккаунт Cloudflare есть, домена нет. Владелец не хочет инджестов и хранения котировок: свечи должны оставаться у биржи.

## Решение

- **Площадка:** один Cloudflare Worker отдаёт SPA как static assets и обслуживает `/api/*`. Не Pages: Cloudflare ведёт новые проекты на Workers со статикой, а два деплоя ради одного сайта — лишний шов и без домена два origin'а.
- **Свечи не хранятся.** Браузер берёт 168 закрытых свечей прямо у биржи, движок считает шаги в браузере, воркер ходит в биржу один раз — при «Поделиться», чтобы снапшот в базе был снят им, а не прислан клиентом. Ни KV, ни cron, ни таблицы котировок — `docs/flows/candles-from-exchange.md`.
- **Хранилище раскладов:** D1. Строка с JSON-снапшотом — около 10 КБ; на бесплатном тарифе база 500 МБ — около 50 тысяч раскладов, на платном 10 ГБ — миллион. Индекс по `(asset, anchor_ts)`.
- **Сборка:** Vite + `@cloudflare/vite-plugin`: `vite dev` поднимает клиент и воркер с локальной D1 одним процессом, `vite build` собирает оба, `wrangler deploy` выкатывает. Vanilla TypeScript без фреймворка — визуал уже написан на нём в `tarot-alpha.html`.
- **Раскладка:** один `package.json`, без воркспейсов. `engine/` — чистые формулы, версионированы папкой; `exchange/` — запросы к биржам, общие для браузера и воркера; `web/` — клиент; `worker/` — маршруты и данные; `migrations/` — SQL для D1. Строка на папку — `docs/README.md`.
- **Аккаунт:** `account_id` прибит в `wrangler.jsonc`, потому что в wrangler залогинено два аккаунта.

## Альтернативы и цена отказа

- **TradingView как источник свечей.** Виджет — iframe без API: из него нельзя ни прочитать свечи, ни дорисовать на нём прогноз. Библиотека lightweight-charts данных не носит, это только рендер. Цена отказа — ничего: как рендер её использовать можно.
- **Кэш свечей в KV.** Снимает лимит биржи по IP колокации, но на бесплатном тарифе KV даёт 1 000 записей в день, а воркер ходит в биржу только при «Поделиться». Вернуться, когда биржа ответит воркеру 429 — это будет видно по событию `share_failed`.
- **Pages для статики + отдельный Worker для API.** Два деплоя одной командой — возможно, но без домена это два origin'а (`pages.dev` и `workers.dev`): CORS, разные куки, разные логи. Лимит CPU у Pages Functions тот же — это те же Workers. `web/` и `worker/` лежат отдельно, разъехаться — правка конфига.
- **Vercel + Neon Postgres.** Два провайдера, холодные старты, ни статики, ни базы в одном месте. Цена отказа — ничего.
- **VPS + Node + SQLite.** Деплой, бэкапы и мониторинг руками у единственного разработчика. Цена отказа — ничего.

## Лимиты, в которые упирается прототип

Статика из Worker'а не запускает скрипт и CPU не тратит; бюджет в 10 мс на запрос — только у `/api/*`, и он одинаков для любой раскладки деплоя. Живой замер — TA-013.

| Ресурс | Бесплатно | Workers Paid, $5/мес | Что нам |
| --- | --- | --- | --- |
| CPU на запрос | 10 мс | 30 с | движок на три шага с сериализацией снапшота — 0,14 мс по тесту-сторожу в `engine/`; OG-картинка satori+resvg — десятки-сотни мс, в бесплатный тариф не влезает |
| D1 | 500 МБ, 100 тыс. записей в день | 10 ГБ | около 50 тысяч раскладов; события воронки — по строке, первыми пойдут под сэмплинг |
| Запросы к воркеру | 100 тыс. в день | 10 млн в месяц | статика не считается |
| Cache API | не работает на `workers.dev` |  | до домена кэшировать нечем, и пока не нужно |

## Последствия

- Рантайм — Workers, не Node: нет `fs`, нет долгих процессов, subrequest выполняется из колокации рядом с пользователем.
- Один движок в двух местах: `engine/` собирается и в бандл страницы, и в воркер. Расхождение исключено кодом, а не проверкой: сервер при записи пересчитывает шаги и хранит свои.
- Тесты воркера — `@cloudflare/vitest-plugin`, не Node-моки.
- OG-картинки — отдельная задача с риском CPU; домен — отдельная задача; прототип живёт на `workers.dev`.
