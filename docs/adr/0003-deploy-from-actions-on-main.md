# ADR-0003 · Деплой из GitHub Actions на пуш в `main`

> реализовано · 2026-09-10 · строка «job `check` на пуш в `main`» отменена `0004-checks-on-pr-only.md`; политику документирования `pre-commit` гоняет по всему репозиторию, а не на изменённых строках — `0010-docs-lint-forgives-nothing.md`; раскатка на Cloudflare идёт из Actions на каждый пуш в `main`, без повторного прогона проверок; токен Cloudflare живёт секретом GitHub; отменяет ADR-0002 в части «деплой руками с машины»

Отменяет ADR-0002. Таблица проверок из него переезжает сюда без изменений.

## Контекст

Владелец мержит PR в GitHub и хочет, чтобы прод обновлялся сам. Деплой с машины требует его сессии wrangler и его присутствия; после первого деплоя (TA-013) это стало единственным ручным шагом между мержем и продом.

## Решение

| Где | Что гоняется |
| --- | --- |
| `pre-commit` на коммит | формат, eslint и `tsc` на застейдженном, политика документирования на изменённых строках |
| Actions, job `check`, на PR и на пуш в `main` | `pnpm install --frozen-lockfile`, `typecheck`, `lint`, `test`, `build`, `prettier --check`, полный аудит `scripts/docs_lint.py` и его тесты |
| Actions, job `deploy`, только пуш в `main` после зелёного `check` | `wrangler d1 migrations apply --remote`, `pnpm run deploy`, `curl /api/health` снаружи |
| нигде | e2e в браузере, нагрузочные |

- **Секрет один:** `CLOUDFLARE_API_TOKEN` в секретах репозитория GitHub; `account_id` не секрет и лежит в `wrangler.jsonc`. Как завести токен и секрет — `docs/runbooks/deploy-workers-dev.md`.
- **Без секрета мерж не краснеет:** шаг деплоя пропускается, пока секрета нет. Иначе первый же мерж после включения был бы красным по причине, не связанной с кодом.
- **Миграции идут перед деплоем** и только добавляющие: воркер со старой схемой на новой миграции не падает, наоборот — падает.
- **Деплой с машины остаётся аварийным путём** и описан в том же runbook: секрет отозван, Actions лежит, нужен откат.

## Альтернативы

- **Деплой руками с машины (ADR-0002).** Не требует токена в GitHub, но связывает прод с одной машиной и одним человеком. Отвергнуто владельцем 2026-09-10.
- **`wrangler-action` вместо `pnpm run deploy`.** Тот же wrangler в обёртке; своя команда деплоя уже собирает клиент и подставляет конфиг из `web/dist`, обёртка ничего не добавляет.

## Последствия

- Токен с правами на Workers и D1 лежит в GitHub — второй канал доступа к аккаунту. Ротация руками в дашборде Cloudflare, затем `gh secret set`.
- Красный `deploy` при зелёном `check` — стоп по правилу «две попытки», потом текст ошибки владельцу; прод остаётся на предыдущей версии, откат не нужен.
